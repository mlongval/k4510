# Code review of the machine — 2026-09-12

Scope: everything in the tree that is code — `core/`, `sdl/`, the ROM and
every program in `demo/`, the language glue, the Tube and CP/M side, the
shell/Python/build scripts, the Linux stick and container, the wasm page,
and the PiDP-11 project (`~/Projects/pidp11`).  Documentation was not
reviewed (Doc: another session does that).  Six readers, one per area,
each file read whole; findings were reproduced where a harness could do
it cheaply (CONFIRMED) and are otherwise by reading (PLAUSIBLE).

The 2026-09-05 review's thirteen fixes were verified in place.  Two of
them had holes, listed below (core 3 and core 5).

**Everything marked FIXED landed the same day, in one commit.**  All 30
C/shell suites pass; `make test` now also runs `nettest.sh` and
`cwdtest.sh`.  ROM after the changes: ROM2 33 free, SW2 16, ROM1A 113.

## Core and frontend

1. **JIM scroll wrote past the end of physical RAM** — CONFIRMED, FIXED.
   `copy_row` did one memcpy of `cols*4` from a start `cellp` had wrapped;
   a text map at $0FFFFF00 with 255 columns segfaulted the harness.  Per
   cell now.
2. **VICKY TRIANGLE memset ran off the end of RAM** — CONFIRMED, FIXED.
   The span was unmasked.  Guarded; and BLIT refuses W×H larger than RAM.
3. **FS_GETCWD with CAP 1–3 crashed the emulator** — CONFIRMED, FIXED.
   `cap - 4` wrapped as size_t (the hole in last week's fix 1).  CAP < 8
   is 8.
4. **OPL2 timers dead after any reset** — CONFIRMED, FIXED.  `opl2_reset`
   zeroed `nalarms` while the chip kept its alarm pointers; after a power
   cycle the AdLib-detect status bits never fired.
5. **The pty read() storm was still there when idle** — CONFIRMED, FIXED.
   Last week's throttle returned early only when the ring was non-empty;
   an interpreter at its prompt (empty ring) still cost 2.9 M read() calls
   per run.  The 100 µs gate is unconditional now.
6. **`ms_ftoa` looped forever on ±inf** — CONFIRMED, FIXED.  MATH_FTOA of
   an overflowed float hung the machine.  inf prints as 1E+38, NaN as NAN.
7. **FS_SAVE/WRITE and N: WRITE honoured a 32-bit LEN** — FIXED.  LEN is
   clamped to RAM; the copies are `fread`/`fwrite` spans, not a call per
   byte (last week's 13 too).
8. **`plat_tcp_send` blocked the whole emulator on a stalled peer** —
   FIXED: sliced 10 s wait, then status 4.
9. **HTTP/TNFS fetch buffers wrapped `cap` at 2 GiB (double free)** —
   FIXED: hard cap at 256 MB.
10. **STAT/CHDIR on ftp/sftp/http downloads the whole file** — OPEN.  A
    HEAD request for curl schemes; noted in TODO.
11. **BBC `CIRCLE` with a huge radius stalled the machine** — FIXED:
    saturating argument parse, radius capped at 4096 units.
12. **Save-state loads restored unchecked indices** — FIXED: keyboard and
    sequencer heads, JIM's reply FIFO and geometry are clamped on load.
13. **Panel "raster" showed the sprite-table pointer** — FIXED.
14. **Reset, power cycle and state load left the Tube child running** —
    FIXED: `io_reset` and `io_state_load` call `tube_stop`; the next
    BBCBASIC used to attach to the old interpreter.
15. **Every emulator fd crossed into `!`, CC, PAS, ssh, stockfish** —
    FIXED: the child closes fds 3+ before exec.
16. **CP/M ignored the configured fs root** (`chdir("fs/CPM")`) — FIXED.
17. **`tube_stop` killed only the direct child** — FIXED: the session.
18. `tube_cp.c` (the in-process Tube, `test/tubetest` only): a start
    cancelled an in-flight kill — FIXED (bounded wait); the fetched-URL
    `FILE*` read freed memory when two were open (last week's 13) — FIXED
    (`fopencookie`, the buffer dies with the FILE); IN_SZ 256 → 4096.
19. **The ULA's OSC parser ate the rest of the session after an OSC ended
    by ESC \\** (tmux and zsh titles through `!`/SSH) — CONFIRMED, FIXED in
    both the ULA (`tula_in`) and the ROM's loop.
20. OPEN: `patch_cpm.py` is not re-runnable (its tube_cp.c patch's anchor
    no longer matches); `*CD` in the in-process BASIC chdir()s the test
    process; the in-process Tube is test-only since the Pi went and
    `io.c`/`tube_cp.h` comments still describe core 3.  Comments in
    `io.h`, `net.h`, `net_plat.h`, `sndq.c` still mention the Pi.

## ROM and the shell's programs

1. **Typing a data file's name at the prompt loaded it whole at $0800**
   — CONFIRMED, FIXED.  `TRACE.TXT` (5 MB) as a typo for `TYPE TRACE.TXT`
   overwrote the font and the screen map.  Only a `.prg` is tried as
   typed now; the same in `RUN`.
2. **FS_LOAD ignored LEN, so EDIT, KOMMANDER F3, LODE's levels, chess's
   configs, RX streams and LOGO files loaded over their own code** —
   CONFIRMED, FIXED at the device: a non-zero LEN is the buffer and a
   longer file gives status 6 with LEN bytes loaded.  The ROM's four raw
   loaders (`k_load`, `do_load`, EXEC, PALETTE) write LEN 0 first; EDIT
   and KOMMANDER STAT first and refuse.
3. **`LOAD name $2000` loaded at address 0** — CONFIRMED, FIXED: a
   non-hex address is an error.
4. **Alias names over 23 bytes overran `want[24]`**, for every unknown
   word ≥ 24 chars typed — CONFIRMED, FIXED: a 96-byte scratch at $BF00
   in the alias bank, above ALIAS_LIMIT.
5. **Accented letters became cursor keys under CP/M, BBC BASIC, `!` and
   TELNET** (é → ESC [ D) — FIXED: a byte ≥ $80 without the key-kind bit
   goes raw.
6. **The IRQ's flat `[$02],Z` ops assumed Z = 0** — FIXED: the IRQ
   pushes Z, zeroes it, restores it (a vblank inside `far_poke16` wrote
   the clock a byte over).
7. **OPLPLAY left the shell in /APPS/OPLPLAY/TUNES**; a tune name over
   31 chars was dropped and DIR_NEXT's 64 bytes overran `fsname[36]` —
   CONFIRMED, FIXED.
8. **RANGER and DELETE built paths past their buffers on a deep cwd** —
   FIXED: `join` refuses.
9. **`PALETTE LOAD <long name>` overran `path[NAMEMAX]`** — FIXED.
10. **`RUN FACE`, `RUN 2048` ran an address** — CONFIRMED, FIXED: the
    program wins when NAME.prg exists.
11. Small: a menu mode change made `k_getin` return CR (ran the
    half-typed line; ESC now); `cmd_run` left `args_tail`; DIR -l's pad
    wrapped for ≥ 9-digit sizes; TELNET's F12 test ignored the kind bit;
    BANNER still said reSID — all FIXED.
12. OPEN: `nav_list`'s `b[256]` is the largest thing on the shell's stack
    (MOUNT list should go through the resident `line`); a ≥ 12-char alias
    lists with no gap; VI's `:s` clobbers the search pattern; BUG's
    `ask()` takes KEY codes as text.

## Games and interpreters

1. **LOGO recursion blew the 256-byte hardware stack** (~40 calls, ~17
   in an expression; `MAXDEPTH 100` never triggered) — CONFIRMED, FIXED:
   `hw_sp()` reads S; `call_proc` and `expr` stop at $30 with "too deep".
   COUNT 80 runs; `F 17` answers "expression too deep" instead of
   crashing.
2. **MS BASIC `*program` killed the machine** (`*SAY HI`: say.prg lands
   inside BASIC, the zero page comes back as the callee's) — CONFIRMED,
   FIXED: star commands go through `SWAP -k`.
3. **RX: a symbol of 16+ characters could not be assigned or used as a
   label — the clause ran as a shell command** — CONFIRMED, FIXED.
4. **RX `D2X(v, 3000)` overran the temp; `LEFT(s,-3)` wrote before it**
   — FIXED.
5. **RX's C-stack guard was dead (2200 > the 1840 bytes that exist) and
   parentheses/unary operators nested unbounded** — FIXED: budget 1500,
   a 12-deep nesting counter in `primary`.
6. **Chess: Esc during an engine's think played an uninitialised move**
   — FIXED.  **The engine was silently dropped once the machine had been
   up 30 s** (`deadline` belongs to the built-in `think`) — FIXED.  **A
   full 256-byte read from a network engine lost a byte** — FIXED.
   **`hist[]` had no bound** — FIXED: a draw at the move limit.
7. **LOGO kept every typed line in the pool** (77 lines and it was full)
   — FIXED.  **RANDOM repeated inside a REPEAT** — FIXED (LCG).  **RT
   with a huge or infinite angle hung and ESC could not break it** —
   FIXED (bounded).
8. **RX `2**1000000000` looped for an hour** — FIXED (exponent capped
   at 64, past which it has overflowed anyway).  `nm[]` overflow on a
   long script name — FIXED.
9. OPEN: chess's port reply buffer is unbounded (~40 BOARD lines in one
   .CMD); RX `RANDOM(5,4)` divides by zero; PARSE patterns copy a clause
   into 160-byte temps; Pascal `Delay(n ≥ 32768)` returns at once;
   `fs/LANG/LOGO/EX/SPIRAL.LGO` is empty.

   FIXED (force-added).
4. **The quadlet copy in the repo and the live one were unrelated
   files** — FIXED: `pidp11 install`.
5. **`telnet-chat.py` mishandled an IAC cut by a recv boundary, dropped
   `IAC IAC`, and spun after the peer closed** — FIXED.

   `!sh` as container root, every disk image writable); restarts are
   not clean guest shutdowns.  Both are in the README now.

## What is sound

The four big fixes of last week are correct (sliced network waits, TNFS
round-robin, sprite buckets, the renderer rewrite: byte-identical on
200 random screens).  `mem.c` is unchanged and tight; `fs_resolve`
never climbs above the root; the guest-name readers are all bounded;
the two child-process paths exec argv arrays with `--`.  The Tube rings
are correct SPSC structures; the pty path reaps without zombies.  The
ROM's segment discipline holds at every cross-bank call traced; the
line editor and VI's slot arithmetic are careful.  The games (BOMBER,
FLUFFY, SKYFIRE, TINY) are clean throughout.  The dangerous scripts
(`build-live.sh`, `install-k4510.sh`) refuse the wrong disk, trap their
cleanup, and bake no secrets into images.  The PiDP-11's exposure is
exactly as claimed: loopback plus the tailnet, nothing on the LAN.

## Test-coverage gaps worth closing

- A blit or text map at the top of RAM; GETCWD with CAP < 8; a `.k4s`
  with out-of-range indices; the OPL2 timers across a reset.
- A file larger than a program's buffer (now: status 6) for EDIT,
  KOMMANDER, LODE, CHESS, LOGO; a data file's name typed alone.
- LOGO recursion past 40; RX long symbols, deep parentheses, `**`.
- TELNET: NAWS, IAC IAC, an IAC split across reads, an accented byte.
- A UCI engine (a fake that answers `bestmove` after 2 s covers three
  chess findings).
- The wasm page (a headless browser clicking early), and a check that
  the bundle holds only tracked files (now in `build.sh`).
- The PiDP-11 entrypoint's rewrite against every `boot.ini` (a dry-run
  script; done by hand today).
