# RX: the Machine’s REXX

`/STARTUP.BAT` is a list of commands, and a list of commands is enough right up to the moment something has to be decided. RX is the answer to that: a REXX for this machine, in the Amiga’s tradition rather than the mainframe’s.

    RX HELLO

runs `HELLO.RX`. So does typing `HELLO` on its own, because the shell’s rule for an unknown word — try it as a program on disk — takes a script as readily as a `.prg`. The scripts that come with the machine are in `/LANG/RX`.

## Why REXX, and what ARexx was

ARexx on the Amiga was two things at once. It was the REXX language — readable, typeless, and forgiving in the way a scripting language for people who are not programmers has to be. And it was the *port* system: every serious Amiga program published a port, so ten lines of REXX could drive a paint program and a terminal in the same script. The second half is why anybody remembers it.

Both halves are here. The language is `demo/rexx.c`, 37 KB loaded at `$0800` because it wants nearly the whole program area, and it is a real one: strings and whole numbers, `PARSE` with its templates, `DO` in all its forms, `SELECT`, internal functions with `PROCEDURE EXPOSE` and recursion, compound (stem) variables, `SIGNAL`, and about fifty built-in functions.

The thing that makes it glue is REXX’s oldest idea: **a clause the interpreter does not recognise is not an error, it is a command**, sent to whatever the current environment is.

    ADDRESS COMMAND
    'DIR APPS'
    IF RC = 0 THEN SAY 'that worked'

## Ports: the file is the mailbox

The Amiga’s ports were message ports between tasks that were all running at once. This machine runs one program at a time, so that arrangement could not be copied — and the substitute is the obvious one: a file.

A script writes its request to `/LANG/RX/MAIL.CMD`, `SWAP`s to the program with that file as its one argument, and reads the reply from `/LANG/RX/MAIL.RPL`: a result code on the first line and the text after it. A program joins the scheme by honouring one argument, which is about twenty lines of work.

`CHESS` is the worked example, and it plays a whole game this way: `NEW`, `MOVE`, `GO`, `LEVEL`, `BOARD`, `FEN` and `STATUS`. Its position lives in `/APPS/CHESS/PORT.GAM`, because a program swapped in starts fresh every time and the file is its memory. `CHESS.RX` in `/LANG/RX` plays against the engine and draws the board itself from what comes back.

!!! note ""
    **Games are good tests.** Wumpus alone found three real faults in the interpreter on the day it was written: `EXPOSE` of a stem was *assigning* it, which silently threw away every member of the caller’s map; `LEAVE` stopped at the first `END` it met rather than the loop’s, so leaving from inside a `SELECT` went nowhere; and a plain `DO` group was counting as a loop. None of them would have shown up in a script that only ran commands in order.

!!! note ""
    **One thing to know about running programs from a script.** A program started by the shell loads at `$6000` — through the middle of the interpreter. So RX asks the filesystem whether the first word of a command names a file: a built-in shell command runs directly and its output stays on the screen, and a program is swapped in and out around the interpreter. That is also why RX uses `SWAP -k` ([Chapter 2, The Shell](02-shell.md)): the ordinary `SWAP` would restore the screen and throw away what the program had just printed for the script to read.
