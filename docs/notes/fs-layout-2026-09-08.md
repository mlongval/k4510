# The machine's filesystem: a layout to grow into

Doc, 2026-09-08: "The filesystem is getting crowded ... I would like your
suggestions."  A proposal, for his ruling.  Nothing here is moved yet.

## What is there now, and why it stopped scaling

    /BBCBASIC  /CHESS  /CPM  /EHBASIC  /FORTH  /MSBASIC  /OPL  /PRG  /RX
    /SYSTEM  STARTUP.BAT  .HELP  .TRASH  (/SHARE in the container)

Three kinds of thing share one level and one shape:

- **languages** (EHBASIC, MSBASIC, BBCBASIC, FORTH, RX): each folder holds
  its interpreter AND its example programs, so the examples are
  indistinguishable from the runtime.
- **/PRG**: 39 files that are system tools (RANGER, VI, DELETE, SETUP,
  SUPERMON), the REXX engine (rx.prg), games (SKYFIRE, BOMBER, CHESS,
  LODE), demos (BALLS, CUBE, MANDEL) and test rigs (KEYTEST, PADTEST),
  all as one alphabet.  Every program written from now on lands here.
- **one program's data as a root folder**: /CHESS is CHESS.PRG's config
  and saved games; /OPL is OPLPLAY's music.  Two more programs with data
  and the root doubles.

And there is no place at all for what the user makes.

## The rule

Every file answers one question: **is it the system's, a language's, a
program's, or yours?**  That gives four folders, plus the two things that
are really other machines or other disks:

    /SYSTEM      the machine's own -- what K/OS looks for by name
    /LANG        the tongues, one folder each: runtime + library + examples
    /APPS        programs that are not tools, one folder each, data beside
    /HOME        yours: documents, projects, what you write and compile
    /CPM         the Z80's disks, A: to P:  (another machine, not a folder)
    /MNT         other disks: /MNT/SHARE, /MNT/USB, ...
    STARTUP.BAT  stays at the root: boot reads the root, nothing else

Six entries at the root, fixed.  New things go one level down.

### /SYSTEM

    /SYSTEM/BIN       the tools as .prg: RANGER KOMMANDER VI EDIT DELETE
                      SETUP SUPERMON BENCH BUG SAY TELNET LOGO PETSCII
                      BANDS KEYTEST PADTEST MOUSETEST
    /SYSTEM/ETC       what the machine reads: PALETTES/, chargen.bin,
                      VI.RC + VI.SAMPLE, STARTUP.SAMPLE, HELP (from .HELP)
    /SYSTEM/LOG       what it writes: PERF.TXT, BENCH-NN.TXT, SETUP.TXT,
                      BUGREPORTS/  (all generated; one .gitignore line)

Reads and writes apart: ETC is tracked, LOG never is.

### /LANG

    /LANG/EHBASIC     ehbasic.prg + README + EX/ (the .BAS demos)
    /LANG/MSBASIC     msbasic.prg
    /LANG/BBCBASIC    the Tube's home dir, LIB/, EX/ (the .BBC demos)
    /LANG/FORTH       forth.prg + README
    /LANG/RX          rx.prg + README + the script library (HELLO WC ...)
    /LANG/PASCAL      the cross-compiled examples WITH THEIR SOURCES:
                      HELLO.PAS + hello.prg, PSIEVE.PAS + psieve.prg ...
    /LANG/C           the same: SIEVE.C + sieve.prg, BALLS.C + balls.prg

The interpreter is the bare name in its folder; the examples under EX/
(or beside the source, for the compiled ones).  PASCAL and C are new: with
`PAS name` and `CC name` at the prompt (built today) a source folder is
where a language lives, and the examples become things you can edit and
recompile on the machine.  Three "hello" programs, one per compiled
language, each next to its .prg, is the tutorial nobody has to write.

### /APPS

    /APPS/CHESS       chess.prg ENGINE.CFG PORT.GAM README  (was /CHESS)
    /APPS/SKYFIRE     skyfire.prg SKYFIRE.CFG
    /APPS/OPLPLAY     oplplay.prg + the .OPL files          (was /OPL)
    /APPS/BOMBER /APPS/LODE /APPS/FLUFFY /APPS/TINY /APPS/BALLS ...

One folder per program, always, even for a single .prg: then a program
that grows a config file or a data set grows in place, and DIR /APPS is
the list of things to run.  I would NOT split games from demos: LODE is
both, and the split is a judgement that changes; a README in the folder
says what it is.

### /HOME

    /HOME             the prompt starts here (STARTUP.BAT: CD /HOME)
    /HOME/PROJECTS/x  a program you are writing: X.PAS, x.prg, notes
    /HOME/DOCS        text
    /HOME/GAMES       CHESS's exported .PGN and the like -- what a program
                      makes FOR you goes here, not into its /APPS folder

RANGER and KOMMANDER open here.  /SHARE-style transfers land here.

### /CPM

Stays, unchanged, at the root.  It is not a folder of ours but a rack of
disks for another CPU, with its own letters and its own USER areas, and
K:0 is already a symlink to the machine's root, so CP/M reaches all of the
above.  Moving it under /LANG or /MNT would make the letters lie.

### /MNT

    /MNT/SHARE        the container's one folder from the host (was /SHARE)
    /MNT/USB          a stick, when the appliance mounts one
    /MNT/HOST         nothing, deliberately: the sandbox rule stands

The network is not here: a URL is a file name (the Meatloaf rule) and
`CD tnfs://host/dir` already makes a remote directory the current one, so
TNFS/FujiNet need no mount point.  A N: device is the same thing from
CP/M's side.  Only things that are really block devices get a /MNT entry.

## The search path, which makes it work

Today bare names are found by `core/io.c` `fs_path()` trying /PRG,
/EHBASIC, /BBCBASIC and /FORTH after the current directory.  Under the new
shape it tries, in order:

    .   /SYSTEM/BIN   /APPS/<NAME>/   /LANG/<NAME>/   /HOME/PROJECTS/<NAME>/

`SKYFIRE` finds /APPS/SKYFIRE/skyfire.prg, `EHBASIC` finds
/LANG/EHBASIC/ehbasic.prg, `RANGER` finds /SYSTEM/BIN/ranger.prg, and a
project of yours runs by name once its .prg exists.  The name-equals-folder
rule is what lets the search stay one stat per step instead of a walk.
The ROM never sees any of this; it is one table on the host side.

RX's `/RX/name.RX` fallback becomes `/LANG/RX/`, tried after the current
directory.

## What it costs

- **Hard-coded paths** (grep'd): 20 sites -- CHESS (5), CPM's K-RUN.SUB
  (kernal, RANGER, KOMMANDER), BENCH/BUG/SETUP/VI under /SYSTEM, SKYFIRE.CFG,
  OPLPLAY's /OPL, REXX's /RX, the Tube's /BBCBASIC/ in bbccon.c, the
  PALETTES prefix.  All constants; an afternoon.
- **Makefile**: the `fs/PRG/%.prg` pattern rule becomes per-folder outputs.
- **Tests**: rangertest and msbasictest look for /PRG and /MSBASIC in prompts.
- **The handbook**: every DIR screenshot and every "/PRG" in the text --
  the handbook session's, and it should recapture after, not before.
- **CP/M's .gitignore** and the K-*.SUB launchers: unchanged (K: is the root).
- **Doc's muscle memory**: `CD PRG` stops working; STARTUP.BAT can carry
  `ALIAS PRG CD /SYSTEM/BIN` for a while.

Not a rewrite.  Do it in one commit with the search path first, so nothing
is unreachable between steps, and move the folders with `git mv` so the
history follows.

## Two things I would not do

- **A /BIN with everything runnable in it.**  It is what /PRG is now, and it
  is the thing that stopped scaling.
- **Case games.**  Folders upper, .prg lower is the habit; the host side
  case-fixes anyway.  Leave it.
