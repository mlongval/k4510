\section{Turbo Pascal 3, on CP/M}
Borland's Turbo Pascal~3 is a CP/M program, so it runs where CP/M runs:
on the Tube's Z80\shipif{chapter:09-cpm}{ (Chapter~\ref{cha:cpm})}, in its own world, exactly as
it did on a Kaypro. You write, compile and run without leaving it, and
what it produces is a CP/M program that runs under CP/M on the Z80 ---
it cannot see VICKY, the OPL2 or anything else on the K4510 side of the
Tube, any more than a Kaypro could.

It is not shipped, because it is Borland's. Put \texttt{TURBO.COM} and
\texttt{TURBO.MSG} into \pth{fs/CPM/H/3} --- the folder that CP/M's
drive \verb|P:| is a shortcut to --- and install it for a ``VT100'' or
``ANSI'' terminal, which is what JIM is. Then, from the K/OS prompt:

\begin{type}
TURBO
\end{type}

\noindent \verb|TURBO| is an alias that \pth{/SYSTEM/ETC/STARTUP.SAMPLE}
defines, for \verb|CPM K-TURBO|: boot CP/M, go to \verb|P:|, start Turbo,
and --- because the submit ends in \verb|EXIT| --- come all the way back
to the K/OS prompt when you leave it.\shipif{chapter:09-cpm}{ Chapter~\ref{cha:cpm}
explains that arrangement.}

\screen{shots/turbo.png}{Turbo Pascal~3 starting on the Z80, its
terminal drawn by JIM.}

Inside, it is 1985. The editor is WordStar's: Ctrl-E, S, D and X move
(the arrow keys are sent as those, so they work too; Home, End, PgUp and
PgDn are not, and do not), and Ctrl-K then D leaves the editor for the
menu. \verb|R| runs the program in memory;
\verb|O| then \verb|C| makes it compile to a \texttt{.COM} you can run
from the CP/M prompt by name.

\section{Mad Pascal, the cross-compiler}
\emph{Mad Pascal} is the other kind entirely --- a cross-compiler, like
the cc65 this machine's ROM is built with. You write on the desktop,
\texttt{mp} compiles to 6502 assembly, MADS assembles it, and the result
is a \texttt{.prg} beside the source in \pth{/LANG/PASCAL} that the
shell's \verb|RUN| loads like any other program --- and, since 2026-09-08,
one the machine can make for itself: \verb|PAS HELLO| compiles
\texttt{HELLO.PAS} in the directory you are standing in
(Chapter~\ref{cha:linux}). It is Tomasz Biela's compiler (MIT), a
Turbo-Pascal-flavoured language with 8-, 16- and 32-bit integers, fixed
and floating point, strings, records, pointers, units and inline
assembly, made for the Atari and since taught the C64, the X16 and the
Neo6502. The K4510 is its newest target.

\begin{type}
PMANDEL
\end{type}

\screen{shots/pmandel.png}{\texttt{PMANDEL}: the Mandelbrot set in text,
sixteen colours through JIM, in 250 frames.}

That is \texttt{demo/pas/pmandel.pas}: the Mandelbrot set, 78 by 28
cells in the machine's sixteen colours, in a little over four seconds
at the desktop's 40.5~MHz --- fixed point, 32-bit integers, forty lines
of Pascal.
\verb|PSIEVE| is the classic sieve, ten passes timed by the frame
counter; \verb|HELLO| prints, shows the colours, and echoes what you
typed after its name. All of them are already compiled and sitting
beside their sources in \pth{/LANG/PASCAL}, so you can run them without
installing anything.

\subsection*{Building}
On the desktop, with FPC and a Mad-Pascal checkout (the installer
patches its target table and rebuilds \texttt{mp}). It looks for the
checkout in \pth{~/Projects/K4510/toolchain/Mad-Pascal} unless
\texttt{MP\_DIR} says otherwise:

\begin{verbatim}
make pascal-install    # once; MP_DIR=... to point elsewhere
make pascal            # fs/LANG/PASCAL/*.PAS -> *.prg beside them
\end{verbatim}

A new program is a file in \pth{fs/LANG/PASCAL}; \texttt{make} finds
it, and so does \verb|PAS| on the machine itself.
The compiled \texttt{.prg} files are committed, so a machine without
the toolchain still runs them, and the test suite (\texttt{test/pastest.sh})
runs \verb|HELLO| and \verb|PSIEVE| through the ROM.

\subsection*{The target}
Everything a Pascal program needs from the machine is in
\texttt{pascal/} of the repository, laid out as it lives inside a
Mad-Pascal checkout: the runtime base (\texttt{base/rtl6502\_k4510.asm}
and \texttt{base/k4510/}), where \texttt{@putchar} writes to JIM, the
terminal (Chapter~\ref{cha:tube}); the SYSTEM and CRT units' machine
halves (\texttt{lib/*\_k4510.inc}); and a \texttt{k4510} unit. The
consequences for the programmer:

\begin{itemize}
\item \verb|Write| and \verb|WriteLn| go through JIM, so the CRT unit is
  the real thing: \verb|GotoXY|, \verb|TextColor| and
  \verb|TextBackground| (the palette's constants: \verb|BLUE|,
  \verb|YELLOW|, \verb|LIGHT_GREEN|\ldots), \verb|ClrScr|, \verb|ClrEol|,
  \verb|InsLine|/\verb|DelLine|, \verb|WhereX|/\verb|WhereY|,
  \verb|CursorOn|/\verb|CursorOff|, \verb|ReadKey| and \verb|KeyPressed|
  on the keyboard device, \verb|Delay| and \verb|Pause| on the frame
  counter, and \verb|Sound| on the machine's sound sequencer --- which
  changed its contract when the OPL2 became the machine's chip:
  \verb|Sound| takes a channel and a pitch in quarter-semitones and
  holds the note until \verb|NoSound|. \verb|TextMode(0)| puts the
  ROM's screen back.
\item \verb|ParamCount| and \verb|ParamStr| come from the shell
  line (\texttt{RUN HELLO one two}, or just \texttt{HELLO one two});
  \verb|ParamStr(0)| is the whole tail.
\item \verb|uses k4510| gives every chip as a typed variable at its
  address --- \verb|VICKY[reg]|, \verb|DMA_SRC|,
  \verb|FS_CMD|, \verb|SYS_FRAMES|, \verb|MATH_F[]|, \verb|TERM_CX|
  and the rest --- plus \verb|FarPeek|/\verb|FarPoke| into the 256~MB
  through the 45GS02's flat addressing, \verb|DmaCopy|/\verb|DmaFill|,
  \verb|Shell('DIR')|, \verb|LoadFile|/\verb|SaveFile| through the ROM,
  \verb|WaitVBlank|, and \verb|TermWrite| for raw escape sequences ---
  each described under \emph{The k4510 unit}, below.
\item Memory: code from \texttt{\$0800}, the program's own; zero page
  \texttt{\$22--\$3F} for the compiler's registers and
  \texttt{\$64--\$A3} for its expression stack (the system calls take
  their arguments in \texttt{\$F0--\$F9}; the ROM has a zero page of its
  own); \texttt{\$0300} the string
  buffer. Programs return to the shell with the ROM's state intact.
\item The program, its variables and the stack that grows above them
  must end below \texttt{\$D000}, where the I/O starts. A program that
  ends within 1~KB of it builds with a warning; one that ends past it
  does not build at all (\texttt{k4510-pas} says where it ended). Big
  tables belong in far memory (\verb|FarPeek|, \verb|DmaCopy|).
\end{itemize}

\subsection*{Floating point on the MATH unit}
\texttt{single} (IEEE-754, 32-bit) does not run in software here. The
runtime's add, subtract, multiply, divide, compare, \verb|Trunc|,
\verb|Round| and \verb|Frac| are the MATH unit at \texttt{\$D700}
(Chapter~\ref{cha:io}): each is a few register moves and one write to
FOP, and the unit answers in the next cycle. \texttt{PFLOAT} times five
thousand rounds of multiply, divide, add and subtract: 5 frames on the
unit, 24 with the software library (assemble with
\verb|mads -d:SOFTFLOAT=1| to get it back for comparison). The
transcendentals are in the \texttt{k4510} unit --- \verb|MathSqrt|,
\verb|MathSin|, \verb|MathCos|, \verb|MathTan|, \verb|MathAtan|,
\verb|MathAtan2|, \verb|MathExp|, \verb|MathLn|, \verb|MathPow|,
\verb|MathFloor| --- one register write each. SYSTEM's own
\verb|Sqrt|/\verb|Sin|/\verb|Cos|/\verb|ArcTan|/\verb|Exp|/\verb|Ln| on
\texttt{single} run on the unit too: the installer patches
\texttt{system.pas} under \verb|{$ifdef k4510}|.

\subsection*{Graphics on VICKY}
\verb|uses graph| draws on VICKY's layer~1: an 8-bit bitmap at
\texttt{\$200000} --- the one BBC BASIC's ULA uses too --- over the
console, which stays visible wherever the picture is transparent
(colour~0), as in a BBC MODE. \verb|InitGraph(0)| draws at the glass the
machine is showing: in one of the panel's integer display resolutions
that glass itself (720$\times$540, 1440$\times$1080, 360$\times$270, up to
1920$\times$1200), in the classic modes 640$\times$480; \verb|GetMaxX| and
\verb|GetMaxY| say which. \verb|InitGraph(1)| asks for 640$\times$480
whatever the glass, putting the console in \verb|MODE 0| for it when it
has to; \verb|CloseGraph| puts the console's mode back. \verb|PutPixel| and \verb|GetPixel| go through the 45GS02's
flat addressing (the MEGA65 multiplier does the row arithmetic);
\verb|Line|, \verb|LineTo| and the K4510 additions \verb|DrawLine|,
\verb|FillBar| and \verb|FillTriangle| are the blitter's LINE, FILL and
TRIANGLE operations --- one register write each; \verb|Circle|,
\verb|Ellipse|, \verb|Rectangle| and the rest of Mad Pascal's generic
GRAPH build on those; \verb|OutTextXY| writes with the console's font.
\verb|PGRAPH| is the demonstration.

\screen{shots/pgraph.png}{\texttt{PGRAPH}: bars, a star and triangles by
the blitter, circles by pixel, text from the ROM's font --- and the
console's own line still on top.}

\subsection*{The k4510 unit}
\verb|uses k4510| is the machine itself, for a program that wants more
than CRT and GRAPH give it. Most of the unit is the chips' registers as
variables at their addresses (below); the rest is ten routines for memory,
files and the shell, and ten for the MATH unit. \texttt{KUNIT} in
\pth{/LANG/PASCAL} runs each of them once, and is the source of the
examples here.

\paragraph{Far addresses.} The unit's addresses are \texttt{cardinal}s:
physical addresses in the 256\,MB, \texttt{\$0000000} to
\texttt{\$FFFFFFF}. The bottom 64\,KB of it is the CPU's own view, so
\verb|cardinal(@buf)| is the far address of a Pascal variable, and the
DMA routines move between the two. While a program runs, the far memory
from \texttt{\$400000} to \texttt{\$FCFFFFF} --- some 249\,MB --- is
its own. Below that the machine keeps the fonts (\texttt{\$10000}) and
the console's screen (\texttt{\$30000}), and GRAPH draws at
\texttt{\$200000}; above it are the ROM, the sideways ROMs and the
shell's own buffers.

\begin{cmdblock}
\cmdentry{FarPeek(a: cardinal): byte}{far memory}{The byte at far
  address \texttt{a}, by the 45GS02's flat addressing.}
\cmdentry{FarPoke(a: cardinal; v: byte)}{far memory}{Writes \texttt{v}
  there.}
\cmdentry{DmaCopy(src, dst, len: cardinal)}{far memory}{Copies
  \texttt{len} bytes; overlapping is safe. The DMA engine has finished
  before the call returns.}
\cmdentry{DmaFill(dst, len: cardinal; v: byte)}{far memory}{Fills
  \texttt{len} bytes with \texttt{v}.}
\cmdentry{LoadFile(const name: string; dest: cardinal): cardinal}{files}{Reads
  the whole file to far address \texttt{dest} and returns its length;
  0 if it could not (no such file --- or an empty one).}
\cmdentry{SaveFile(const name: string; src, len: cardinal): boolean}{files}{Writes
  \texttt{len} bytes from \texttt{src} to the file, replacing it; true if
  it worked.}
\cmdentry{Shell(const cmd: string)}{the shell}{Runs one line as if typed
  at the prompt: \texttt{DIR}, \texttt{CD}, \texttt{COPY}, \texttt{MKDIR},
  \texttt{ECHO} and the rest. Its output goes to the screen; the result is
  the byte at \texttt{\$03FF} (Chapter~\ref{cha:memory}), 0 if the
  command worked --- read it straight after: it is the last byte of the
  runtime's string buffer, and the next string operation may overwrite it.}
\cmdentry{WaitVBlank}{timing}{Waits for the next frame, a sixtieth of a
  second. \texttt{SYS\_FRAMES} is the frame count's low byte, for timing.}
\cmdentry{TermWrite(const s: string)}{the terminal}{Sends \texttt{s} to
  JIM unchanged, VT100 escape sequences and all.}
\cmdentry{MathSqrt, MathSin, MathCos, MathTan, MathAtan, MathExp, MathLn,
  MathFloor (x: single): single}{MATH unit}{One write to the unit each;
  angles in radians, \texttt{MathLn} the natural log.}
\cmdentry{MathAtan2(y, x: single): single}{MATH unit}{The angle of the
  point (x,\,y), $-\pi$ to $\pi$.}
\cmdentry{MathPow(x, y: single): single}{MATH unit}{$x^y$.}
\end{cmdblock}

\noindent Names and command lines are cut at 95 characters, the length
of the shell's own line; a name is the shell's too, relative to the
current directory or from \pth{/}.

\begin{verbatim}
uses k4510;
const FAR0 = $400000;
var buf: array[0..255] of byte;
    RC: byte absolute $03FF;            { the shell's result }
    len: cardinal;
begin
  DmaFill(FAR0, 256, 0);
  FarPoke(FAR0 + 7, 99);
  DmaCopy(FAR0, cardinal(@buf), 256);   { far -> buf: buf[7] = 99 }
  if SaveFile('/HOME/DATA.BIN', FAR0, 256) then
    len := LoadFile('/HOME/DATA.BIN', FAR0 + $1000);   { 256 }
  Shell('CD /NO-SUCH-DIR');             { RC <> 0: it failed }
end.
\end{verbatim}

\paragraph{The registers.} Every chip is a variable at its address, typed
to fit, under the names of Appendix~\ref{cha:registers}: \verb|VICKY[]|
(the 256 bytes at \texttt{\$D000}), the keyboard (\verb|KBD| pops the next
key, \verb|KBDST| says whether one is waiting and which modifiers are
down), \verb|DMA_SRC|/\verb|DST|/\verb|LEN|/\verb|CMD|, the file
system's \verb|FS_CMD| and its friends (with the \verb|FS_OPEN_READ|\ldots
command constants), \verb|SYS[]| and \verb|SYS_FRAMES|, the MATH unit's
\verb|MATH_F[0..7]| and \verb|MULTINA|/\verb|MULTINB|/\verb|MULTOUT|,
\verb|TUBE[]|, \verb|NET[]|, and JIM's \verb|TERM|, \verb|TERM_CX|,
\verb|TERM_CY|, \verb|TERM_FG|, \verb|TERM_BG| and the rest. Reading or
writing one is a single load or store.

\paragraph{A bank window.} \verb|FarPeek| is a call per byte. For a
block of far memory used as an ordinary array --- indexed, at full speed
--- point an 8\,KB block of the CPU's view at it with a bank register
(Chapter~\ref{cha:memory}) and declare the array \verb|absolute| there.
The unit has no names for the bank registers; declare the one you use:

\begin{verbatim}
var win: array[0..8191] of byte absolute $8000;   { block 4 }
    BANK4: cardinal absolute $D610;               { $D600 + 4*4 }
    BANK4HI: byte absolute $D613;
begin
  BANK4 := $400000;      { open: win[] is $400000-$401FFF }
  win[100] := 1;         { lands in far memory }
  BANK4HI := $FF;        { shut: $8000 is the program's RAM again }
end.
\end{verbatim}

\noindent Writing the whole \texttt{cardinal} switches the block on as
well (its top byte has bit~7 clear); \texttt{\$FF} in that byte switches
it off. Block $n$ is \texttt{\$2000}$\times n$ to
\texttt{\$2000}$\times n +$\texttt{\$1FFF}. Use one the program does
not occupy --- its code and variables run up from \texttt{\$0800}
(\texttt{BANKWIN}'s end at \texttt{\$137A}, so blocks 1 to 4 are
free) --- and never 0 (zero page and stack) or 5 to 7, which the ROM
banks in and out around every system call. \texttt{BANKWIN} is the
full demonstration, timed against \verb|FarPeek|: the window sums
64\,KB in 8 frames, \verb|FarPeek| in 17.

\paragraph{The rules.}
\begin{itemize}
\item \textbf{Code stays in the 64\,KB}; data does not have to. A
  program is at most \texttt{\$0800}--\texttt{\$CFFF}, 50\,KB with its
  variables; everything else goes in far memory.
\item \textbf{Do not \texttt{Shell} a program.} \verb|RUN| loads the
  other program over yours (Pascal programs load at \texttt{\$0800},
  C programs at \texttt{\$6000}) and there is nothing to come back to.
  The shell's own commands are fine.
\item \textbf{Inline assembly that borrows \texttt{:bp}} must put its
  low byte back to 0. Mad Pascal indexes any array over 256 bytes
  through \verb|(:bp),y| and counts on it; the unit's own routines
  restore it.
\end{itemize}

\section{The library reference}\label{sec:paslib}
What follows is every routine the K4510 target adds to Mad Pascal, unit by
unit, with what it does and a small example. (The \verb|k4510| unit, which
reaches the machine's memory, files and registers, is described above,
under \emph{The k4510 unit}.) Where a routine is Mad Pascal's
own and merely runs on this machine (\verb|WriteLn|, \verb|Inc|\ldots) it is
not repeated; Mad Pascal's own documentation has those.

\medskip\noindent\textbf{Every example in this section is untested.} They were
written from the units' source, not compiled and run: the Mad Pascal toolchain
was not to hand when this section was written. Each one is a few lines that
should compile as shown; if one does not, the source in \pth{pascal/mp/lib}
is the authority and the example is wrong.

\medskip\noindent A program names the units it wants on its \verb|uses| line.
\verb|crt|, \verb|graph| and \verb|k4510| are always there to name. The
\verb|bbc| unit is a program in \pth{/LANG/PASCAL/EX} (\texttt{BBC.PAS}); to
use it, keep a copy of \texttt{BBC.PAS} beside your own program, because
\verb|PAS| finds units in the directory it compiles in.

\subsection*{CRT: the screen, the keyboard, the clock and the sound}
\verb|uses crt|. Everything is drawn through JIM, the terminal
(Chapter~\ref{cha:tube}), so the screen is the console's own 80 columns by
30 rows. Columns and rows count from 1, as in Turbo Pascal.

\paragraph{\texttt{ClrScr}} Clears the screen and puts the cursor at the top
left.

\paragraph{\texttt{GotoXY(x, y: byte)}} Moves the cursor to column \verb|x|,
row \verb|y|. The next \verb|Write| lands there.

\paragraph{\texttt{WhereX: byte}, \texttt{WhereY: byte}} The cursor's column
and row.

\paragraph{\texttt{TextColor(c: byte)}, \texttt{TextBackground(c: byte)}} The
colour of the letters, and of the cell behind them, for everything written
afterwards. \verb|c| is a palette index 0 to 15. The names are constants:
\verb|BLACK|, \verb|WHITE|, \verb|RED|, \verb|CYAN|, \verb|PURPLE|,
\verb|GREEN|, \verb|BLUE|, \verb|YELLOW|, \verb|ORANGE|, \verb|BROWN|,
\verb|LIGHT_RED|, \verb|DARK_GREY|, \verb|GREY|, \verb|LIGHT_GREEN|,
\verb|LIGHT_BLUE| and \verb|LIGHT_GREY| --- the Commodore 64's sixteen.

\paragraph{\texttt{ClrEol}} Clears from the cursor to the end of the line.

\paragraph{\texttt{InsLine}, \texttt{DelLine}} Insert an empty line at the
cursor's row, pushing the rest down; delete the cursor's row, pulling the rest
up.

\paragraph{\texttt{CursorOn}, \texttt{CursorOff}} Show or hide the cursor.

\paragraph{\texttt{KeyPressed: Boolean}} True when a key is waiting. It does
not take the key.

\paragraph{\texttt{ReadKey: char}} The next key, waiting for one if there is
none. Arrow and function keys come as the machine's key codes, not as Turbo
Pascal's two-character sequences.

\paragraph{\texttt{Delay(ms: word)}} Waits about \verb|ms| milliseconds. The
clock is the frame counter, so the wait is rounded to frames of 16.7~ms.

\paragraph{\texttt{TextMode(mode: byte)}} Puts the ROM's screen and palette
back, and resets JIM. \verb|mode| is ignored; \verb|TextMode(0)| is the
spelling.

\paragraph{\texttt{Sound(chan, freq, dist, vol: byte)}} Starts a note on the
sound sequencer, which plays it on the OPL2. \verb|chan| is 0 to 2 for the
three tone channels, 3 for noise. \verb|freq| is the pitch in quarter
semitones: 53 is middle C and every semitone is 4 more. \verb|dist| is
ignored (it is there for Turbo Pascal's signature). \verb|vol| is 0 to 15,
the BBC's \verb|SOUND| amplitude without its minus sign: 15 is loudest. The
note holds until \verb|NoSound| or the next \verb|Sound| on that channel.

\paragraph{\texttt{NoSound}} Silences every channel.

\noindent\emph{Example (untested):} a coloured menu, a key, and a note.

\begin{verbatim}
program crtdemo;
uses crt;
begin
  ClrScr;
  TextColor(YELLOW); TextBackground(BLUE);
  GotoXY(10, 5);  Write(' K4510 menu ');
  TextColor(WHITE); TextBackground(BLACK);
  GotoXY(10, 7);  Write('1  play a note');
  GotoXY(10, 8);  Write('Q  quit');
  repeat
    case UpCase(ReadKey) of
      '1': begin
             Sound(0, 53, 0, 12);   { middle C on tone channel 0 }
             Delay(500);
             NoSound;
           end;
    end;
  until False;   { Q is handled below in a real program }
end.
\end{verbatim}

\subsection*{SYSTEM: time, chance and the command line}
These are the machine's halves of Mad Pascal's own SYSTEM unit, so they need
no \verb|uses|.

\paragraph{\texttt{Pause}, \texttt{Pause(n: word)}} Wait one frame, or
\verb|n| frames (a sixtieth of a second each). Unlike \verb|Delay| it asks
the frame counter directly, so \verb|Pause(60)| is a second exactly.

\paragraph{\texttt{Randomize}} Seeds the generator from the clock.

\paragraph{\texttt{Random(range: byte): byte}, \texttt{Random(range: smallint): smallint}}
A random number from 0 up to \verb|range - 1|.

\paragraph{\texttt{Random: Real}, \texttt{RandomF: Float}} A random fraction,
at least 0 and below 1, as a fixed-point \verb|Real| or a \verb|single|.

\paragraph{\texttt{ParamCount: byte}, \texttt{ParamStr(i: byte): string}} The
words after the program's name on the shell line. \verb|ParamStr(1)| is the
first; \verb|ParamStr(0)| is the whole tail, spaces and all.

\noindent\emph{Example (untested):} \verb|DICE 6 3| rolls three six-sided dice.

\begin{verbatim}
program dice;
var sides, n, i: byte;
begin
  Randomize;
  sides := 6; n := 1;
  if ParamCount >= 1 then sides := StrToInt(ParamStr(1));
  if ParamCount >= 2 then n := StrToInt(ParamStr(2));
  for i := 1 to n do Write(Random(sides) + 1, ' ');
  WriteLn;
end.
\end{verbatim}

\subsection*{GRAPH: lines, bars and text on VICKY}
\verb|uses graph|. A picture one byte a pixel, on VICKY's layer~1 over the
console, as big as the glass (\verb|GetMaxX| by \verb|GetMaxY|). Pixels count from 0, \verb|(0,0)| is the top left, and
colour~0 is transparent, so the console's text shows through wherever nothing
is drawn. Colours are palette indexes; 0 to 15 are the same sixteen as CRT's.
Anything off the screen is quietly dropped.

\paragraph{\texttt{InitGraph(0)}} Points the layer at the bitmap, sized to
the glass the machine is showing, and clears it. Call it first, and place
things by \verb|GetMaxX| and \verb|GetMaxY| rather than by numbers:
\pth{PGRAPH.PAS} draws the same picture at 640$\times$480 and at
1440$\times$1080. \verb|InitGraph(1)| (\verb|GFX_VGA|) is 640$\times$480
always, as the unit was until alpha-0.9: in an integer display resolution
it puts the console in \verb|MODE 0| first, and \verb|CloseGraph| puts the
resolution back --- the BBC unit asks for it, because its sprites live at
\texttt{\$260000}, just above a 640$\times$480 bitmap. (\verb|InitGraph(driver, mode, path)|
is accepted too, for programs written for other Mad Pascal
targets; it does the same as \verb|InitGraph(mode)|.)

\paragraph{\texttt{CloseGraph}} Switches the picture off and puts the
console's video mode back. A program that does not call it leaves the
picture up after it ends.

\paragraph{\texttt{ClearDevice}} Clears the whole bitmap to transparent, by
the DMA engine. Instant.

\paragraph{\texttt{SetColor(c: byte)}} The colour of everything drawn next.

\paragraph{\texttt{SetBkColor(c: byte)}} The ground colour VICKY shows where
neither the picture nor the text has anything.

\paragraph{\texttt{PutPixel(x, y)}, \texttt{PutPixel(x, y, c)}}
One pixel (\verb|x|, \verb|y| are \verb|smallint|, \verb|c| a \verb|byte|), in the
current colour or the colour given.

\paragraph{\texttt{GetPixel(x, y: smallint): byte}} The colour of a pixel;
0 when it is off the screen.

\paragraph{\texttt{DrawLine(x0, y0, x1, y1: smallint)}} A line between two
points. The blitter draws it: one register write each, with no loop in
Pascal.

\paragraph{\texttt{LineTo(x, y: smallint)}, \texttt{LineRel(dx, dy: smallint)}}
A line from the current position (which starts at 0,0 and is wherever the
last line ended) to a point, or by a distance.

\paragraph{\texttt{FillBar(x0, y0, x1, y1: smallint)}} A filled rectangle by
the blitter. The corners may be in any order, and a bar that hangs off the
edge is clipped.

\paragraph{\texttt{FillTriangle(x0, y0, x1, y1, x2, y2: smallint)}} A filled
triangle by the blitter.

\paragraph{\texttt{OutTextXY(x, y: smallint; s: string)}} Draws \verb|s| into
the picture with the console's 8 by 8 font, its top left at \verb|x,y|, in the
current colour.

\noindent Mad Pascal's own generic routines --- \verb|Circle|,
\verb|Ellipse|, \verb|Rectangle|, \verb|MoveTo| and the rest --- are built on
these and work as they do on the other targets.

\noindent\emph{Example (untested):} a frame, a star and a caption.

\begin{verbatim}
program gdemo;
uses crt, graph;
var i: byte;
begin
  InitGraph(0);
  SetColor(BLUE);   FillBar(40, 40, 600, 440);
  SetColor(YELLOW); FillTriangle(320, 80, 220, 300, 420, 300);
  SetColor(WHITE);
  for i := 0 to 15 do DrawLine(320, 240, 40 + i * 35, 440);
  OutTextXY(240, 450, 'HELLO, VICKY');
  ReadKey;
  CloseGraph;
end.
\end{verbatim}

\subsection*{BBC: the Tube ULA's drawing and sound, in Pascal}
\verb|uses bbc|. A port of BBC BASIC's graphics and sound words, so that a
Pascal program draws and sounds as its \texttt{.BBC} original does. It sits
on GRAPH and keeps the BBC's own world: coordinates run 1280 by 1024 from the
\emph{bottom} left, and are scaled onto the 640 by 480 bitmap; logical
colours are the BBC's, in palette entries 16 to 31; sound is the sequencer
with the BBC's units. Every routine is the BBC word with a \verb|B| in front.
The eleven ports in \pth{/LANG/PASCAL/EX} are all written with it.

\paragraph{\texttt{BMode(n: byte)}} \verb|MODE n|. 1 and 5 give four colours, 2
gives sixteen, any other graphics mode two. 3, 6 and 7 put
the bitmap away and the console back. It clears the screen and sets the
mode's default colours and \verb|GCOL|.

\paragraph{\texttt{BGcol(c: byte)}} \verb|GCOL 0,c|: the colour drawn with,
\verb|c| below 128; 128 and up sets the background that \verb|BClg| clears
to.

\paragraph{\texttt{BPalette(l, p: byte)}, \texttt{BPaletteRGB(l, r, g, b: byte)}}
\verb|VDU 19|: logical colour \verb|l| shows physical colour \verb|p| (0 to 7,
the bits are red, green, blue), or the exact red, green and blue given.

\paragraph{\texttt{BOrigin(x, y: smallint)}} \verb|ORIGIN x,y|.

\paragraph{\texttt{BMove(x, y: smallint)}, \texttt{BDraw(x, y: smallint)}}
\verb|MOVE| and \verb|DRAW|: put the graphics cursor somewhere without
drawing, or draw a line to a point from the cursor.

\paragraph{\texttt{BPlot(k: byte; x, y: smallint)}} \verb|PLOT k,x,y|. Of its
many kinds this one does 4 and 5 (move and draw), 69 (a point), 85 (a triangle
with the two points before), 101 (a rectangle with the point before) and 237
(a sprite).

\paragraph{\texttt{BClg}} \verb|CLG|: the bitmap filled with the background.

\paragraph{\texttt{BCircle(x, y, r: smallint)}, \texttt{BCircleFill(x, y, r: smallint)}}
\verb|CIRCLE| and \verb|CIRCLE FILL|, centre and radius in BBC units.

\paragraph{Sprites} The machine has 128 hardware sprites; VICKY moves them, so
a program draws once and moves for nothing.
\verb|BSpriteCapture(n, w, h)| makes sprite \verb|n| from the \verb|w| by
\verb|h| pixels (8, 16, 32 or 64) whose bottom left is at the graphics cursor
(\verb|VDU 23,27,1|). \verb|BSpriteSelect(n)| chooses the sprite \verb|PLOT 237|
will move. \verb|BSpritePlot(x, y)| places the selected sprite with its
bottom left at \verb|x,y|. \verb|BSpriteShow(n, m)| makes sprite \verb|n|
show sprite \verb|m|'s picture, so one picture serves many sprites.
\verb|BSpriteFlip(n, f)| flips it (bit~0 across, bit~1 up and down),
\verb|BSpriteHide(n)| hides it, and \verb|BSpritesOff| turns the layer off.

\paragraph{\texttt{BSound(ch, amp, pitch, dur)}}
\verb|SOUND ch,amp,pitch,dur| (\verb|amp| is a \verb|shortint|, the rest \verb|byte|). \verb|ch| is 0 for noise, 1 to 3 for the
tones. \verb|amp| is 0 down to $-15$. \verb|pitch| is in quarter semitones, 53
being middle C. \verb|dur| is in twentieths of a second, and 255 holds the
note. The notes are queued: the sequencer keeps 64 a channel, so a whole tune
can be sent at once and it plays while the program goes on or ends.
\verb|BSoundOff| silences every channel and empties the queues.

\paragraph{\texttt{BWait(cs: word)}} \verb|WAIT|, in centiseconds, rounded to
frames.

\paragraph{\texttt{BRnd(n: word): word}, \texttt{BRandomize}} \verb|RND(n)|:
1 to \verb|n|, from a 32-bit generator --- Mad Pascal's own \verb|Random| is
a 16-bit one whose pairs fall on a lattice, which the lines of \texttt{KALEID}
showed up. \verb|BRandomize| seeds it from the clock.

\paragraph{\texttt{BSx(x)}, \texttt{BSy(y)}} A BBC coordinate as a bitmap
column or row, for a program that wants to mix \verb|BDraw| with GRAPH's
\verb|PutPixel|.

\noindent\emph{Example (untested, except for the sound, which is TUNE's):}
a mode~2 picture with a held chord.

\begin{verbatim}
program bbcdemo;
uses crt, k4510, bbc;
begin
  BMode(2);                         { sixteen colours }
  BGcol(1);  BCircleFill(640, 512, 300);
  BGcol(7);  BMove(100, 100); BDraw(1180, 924);
  BPaletteRGB(8, 255, 128, 0);      { colour 8 is orange }
  BGcol(8);  BPlot(101, 900, 200);  { a rectangle from the cursor }
  BSound(1, -12, 53, 255);          { C, held }
  BSound(2, -12, 69, 255);          { an octave above, held }
  ReadKey;
  BSoundOff;
  BMode(7);                         { the console back }
end.
\end{verbatim}

\subsection*{Things this Mad Pascal does differently}
Found while writing the demos; each cost an hour once.

\begin{itemize}
\item \verb|Result| holds a function's value, and \verb|Exit(value)| sets it
  and leaves at once --- the BBC's \verb|= value|. \texttt{FUNCS.PAS} is the
  example.
\item A function's local variables, \verb|Result| included, are \emph{static}:
  one copy, shared by every call. So \verb|Join(Join(a, b), c)| gives the outer
  call the inner one's \verb|Result|. Call them one after the other into
  variables.
\item Strings are joined with \verb|Concat(a, b)|, two at a time. \verb|+| on
  strings is a syntax error with a literal first and, with variables, compiles
  to an address sum.
\item Pascal ignores case, so a variable called \verb|page| and a constant
  called \verb|PAGE| are the same thing.
\item A local array's own name is a pointer to it. To hand its address to a
  routine in assembly, write \verb|adr.buf|, not \verb|buf|.
\end{itemize}
